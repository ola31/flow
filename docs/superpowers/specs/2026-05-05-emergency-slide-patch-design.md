# 라이브 중 슬라이드 긴급 수정 설계 (Emergency Slide Patch)

- **작성일**: 2026-05-05
- **상태**: 설계 승인 대기 → 구현 플랜
- **대상 워크플로**: 마크다운 곡 (`slides.md`) 한정. PPT 곡은 본 기능에서 제외.

## 배경

라이브 송출 도중 가사 오타를 발견하는 상황이 종종 있다. 현재 Flow는 `LiveController._is_live`로 모든 편집 엔트리포인트를 차단하기 때문에, 송출을 중단하지 않고는 가사를 고칠 방법이 없다. 송출을 중단하는 것은 예배 흐름을 끊으므로 사실상 불가능하다.

마크다운 곡의 슬라이드 렌더링은 LibreOffice 등 외부 도구에 의존하지 않고 `services/markdown/renderer.py`에서 QPainter로 직접 그리기 때문에, 텍스트 변경을 수 밀리초 안에 새 이미지로 만들 수 있다. 이 점을 활용하여 라이브 도중에도 안전하게 텍스트를 고치고 즉시 디스플레이에 반영할 수 있도록 한다.

원본 `slides.md`는 건드리지 않는다. 수정 내용은 별도 "패치 파일"에 저장되어 곡과 함께 따라다니며, 라이브 종료 후 일반 편집 모드로 돌아왔을 때 사용자에게 정리(원본 반영 또는 폐기)하도록 유도한다.

## 핵심 결정

| 항목 | 선택 | 이유 |
|---|---|---|
| 적용 범위 | 마크다운 곡 한정 | PPT는 외부 도구 필요, in-app 편집 불가 |
| UI 형태 | 라이브 화면 좌우 분할 | 팝업은 라이브 화면 가림. 분할은 송출과 편집 동시 가능 |
| 진입 | 우클릭 → "긴급 수정" 메뉴 | 명시적이고 실수 방지 |
| 포커스 | Tab 토글 + 마우스 클릭 | 키보드만으로도 운용 가능 |
| 적용 모델 | 명시적 확인 (Ctrl+Enter) | 자동 저장 시 청중 화면에 미완성 텍스트 노출 위험 |
| 저장 형식 | `<song_dir>/.patches.json` | 곡 단위 부착, 다른 프로젝트에서도 따라옴 |
| 슬라이드 식별 | 본문 해시 우선, 인덱스 fallback | 원본 .md 편집 후에도 매칭 시도 가능 |
| 라이브 종료 후 | 일반 편집 모드 진입 시 알림 바 | 임시 패치를 결국 정리하도록 유도 |

## UX 명세

### 진입

라이브 모드에서 다음 두 위치 중 한 곳을 우클릭하면 컨텍스트 메뉴에 **"긴급 수정"** 항목이 보인다.

1. 스코어 캔버스의 **핫스팟** — 그 핫스팟이 가리키는 슬라이드를 편집
2. 슬라이드 프리뷰/썸네일의 **슬라이드 이미지** — 그 슬라이드를 편집

해당 슬라이드의 소스가 마크다운이 아닌 경우(원본 곡이 PPT로 만들어진 경우) "긴급 수정" 항목은 비활성(disabled)으로 표시한다. 툴팁: "PPT 곡은 외부 편집 필요".

### 분할 레이아웃

"긴급 수정" 클릭 시 라이브 화면이 좌우로 분할된다.

```
┌──────────────────┬───────────────────────────────────┐
│                  │                                   │
│  편집 패널       │  라이브 패널 (기존 라이브 UI)     │
│  (좌측, 40%)     │  (우측, 60%)                      │
│                  │                                   │
│  - 헤더          │  - 스코어 캔버스 + 핫스팟         │
│    · 닫기 버튼   │  - 슬라이드 프리뷰                │
│    · 원본 되돌리기│  - 라이브 컨트롤 (Verse, Live)   │
│  - 마크다운 입력 │                                   │
│  - 미리보기      │                                   │
│  - 적용 버튼     │                                   │
│                  │                                   │
└──────────────────┴───────────────────────────────────┘
```

좌측 비율은 40% 가량을 디폴트로 한다. 사용자가 분리바를 드래그해 조정할 수 있다.

편집 패널을 닫으면 (닫기 버튼 또는 Esc, 변경사항 처리 후) 우측이 다시 풀스크린이 된다.

### 포커스 모델

분할 상태에서 키보드 포커스는 두 패널 중 한쪽에만 있다.

- **Tab** 키 — 좌우 패널 토글
- **마우스 클릭** — 클릭한 패널 활성화
- 활성 패널: 좌측 3px **ACCENT** (`#5b8def`) 바 + 배경을 `SURFACE` → `ELEVATED` 톤으로 살짝 밝게
- 비활성 패널: 약간 어둡게 (오버레이로 5% 톤다운)

키 라우팅:
- **라이브 패널 활성 시**: 기존 라이브 단축키가 모두 정상 동작 (Space, 방향키, 숫자키, Enter, B, Esc, …)
- **편집 패널 활성 시**: 같은 키들이 텍스트 편집기로 전달됨. 기존 라이브 단축키는 동작하지 않음.

라이브 패널의 기존 키 핸들러는 `if self._is_live:` 체크 외에 "편집 패널이 활성인지"도 확인하도록 한다. (`_emergency_patch_active and _patch_focus == "editor"` 같은 조건)

Tab 키는 두 패널 모두에서 가로채야 한다. QPlainTextEdit 기본 동작(탭 문자 삽입)은 비활성화한다.

### 편집 패널 구성

```
┌──────────────────────────────────────┐
│ 긴급 수정 — 슬라이드 #3        [×]  │  ← 헤더
│                       [원본으로 되돌리기] │
├──────────────────────────────────────┤
│                                      │
│  주의 사랑은 측량할 수 없네           │  ← 텍스트 입력 (QPlainTextEdit)
│  영원토록 변함이 없네                 │
│                                      │
│                                      │
├──────────────────────────────────────┤
│ ┌──────────────────────────────────┐ │
│ │                                  │ │  ← 미리보기 (작은 슬라이드 이미지)
│ │  [렌더링된 슬라이드 미리보기]    │ │
│ │                                  │ │
│ └──────────────────────────────────┘ │
├──────────────────────────────────────┤
│            [적용 (Ctrl+Enter)]       │  ← 적용 버튼
└──────────────────────────────────────┘
```

- **헤더**: 슬라이드 식별자(번호 또는 절 이름), 닫기 버튼, "원본으로 되돌리기" 버튼
- **텍스트 입력**: 슬라이드의 마크다운 본문만 (frontmatter 제외). 프로젝트 마크다운 하이라이터 적용
- **미리보기**: 텍스트 변경 시 즉시 갱신되는 작은 슬라이드 이미지 (운영자만 본다)
- **적용 버튼**: 클릭 또는 Ctrl+Enter

미리보기는 `services/markdown/renderer.py`의 `render_slide()`를 호출해 만들고, frontmatter는 곡 원본 것을 그대로 사용한다.

### 편집 적용 (확인)

**Ctrl+Enter** 또는 적용 버튼:

1. 현재 편집기 텍스트로 패치 객체를 만들고 `.patches.json`에 저장
2. SlideManager에 변경 통보 → 해당 슬라이드 캐시 무효화
3. 디스플레이가 그 슬라이드를 송출 중이면 즉시 새 이미지로 교체
4. 편집 패널 닫기, 풀스크린 라이브 복귀

송출 중이 아닌 슬라이드를 편집한 경우에도 (1)(2)는 동일하게 일어난다. 다음에 그 슬라이드가 송출되는 시점에 자연스럽게 패치된 버전이 나간다.

### 닫기 (Esc 또는 닫기 버튼)

닫을 때 변경사항 처리 분기:

- **편집기 텍스트 == 패널 열렸을 때 텍스트** (이번 세션 변경 없음): 즉시 닫기
- **변경사항 있음**: 확인 다이얼로그 표시

확인 다이얼로그:

```
┌───────────────────────────────────┐
│ 변경사항을 적용할까요?            │
│                                   │
│         [ 적용 ]   [ 버리기 ]     │
└───────────────────────────────────┘
```

- 기본 포커스: **적용** (왼쪽)
- **← →** 키로 옵션 이동
- **Enter** 로 결정 실행
- 다이얼로그에서 **Esc** 누르면 다이얼로그 닫고 편집 상태로 복귀 (실수 보호)

선택 결과:
- **적용**: 위 "편집 적용" 흐름과 동일
- **버리기**: 패치 파일 변경 없음(기존 패치가 있었다면 그대로 유지). 편집 패널만 닫기

### 원본으로 되돌리기

헤더 버튼. 이 슬라이드에 기존 패치가 있다면 패치 파일에서 제거하고 편집 패널을 닫는다. 디스플레이가 그 슬라이드를 송출 중이면 즉시 원본 이미지로 교체.

기존 패치가 없는 상태에서 누르면 (편집 진행 중이지만 아직 적용 안 함) 편집 내용을 폐기하고 닫는 동작이다 — 즉 "취소 + 패치 해제"의 통합 액션.

### 시각 표시

- **편집 중**: 좌측 패널 헤더에 큼지막한 **AMBER** 배지 "긴급 수정 중"
- **패치된 슬라이드 표시**: 운영자용 슬라이드 썸네일/프리뷰 우상단에 작은 **AMBER** 닷
  - 핫스팟 위에는 표시하지 않음 (캔버스가 이미 복잡함)
  - 디스플레이(청중 화면)에는 절대 표시하지 않음
- 라이브 패널이 비활성일 때(편집 패널 활성 시): 라이브 패널 위에 5% 톤다운 오버레이

## 데이터 모델

### 패치 파일: `<song_dir>/.patches.json`

```json
{
  "version": 1,
  "patches": [
    {
      "id": "uuid-string",
      "slide_hash": "sha256:abc123...",
      "slide_index": 2,
      "patched_main": "주님의 사랑은 측량할 수 없네\n영원토록 변함이 없네",
      "created_at": "2026-05-05T19:42:11Z",
      "created_during": "live"
    }
  ]
}
```

필드:
- **id**: 패치 고유 ID. UI에서 패치 단위 액션 식별용
- **slide_hash**: 패치 적용 시점의 원본 슬라이드 본문(`Slide.main`) 해시. 매칭 키
- **slide_index**: 패치 적용 시점의 슬라이드 인덱스. 해시 매칭 실패 시 fallback
- **patched_main**: 패치된 본문 텍스트 (마크다운 형식, 슬라이드 한 블록)
- **created_at**: ISO 8601 타임스탬프
- **created_during**: `"live"` (라이브 중 만든 긴급 수정) — 향후 다른 컨텍스트 추가 가능

`patched_main`은 슬라이드 한 블록의 본문만 저장한다. frontmatter나 다른 슬라이드 영향 없음.

파일 이름 앞의 `.` 는 일부러 — 곡 폴더에서 시각적으로 덜 두드러지게 하고, 실수로 git에 안 올라가도 .gitignore 패턴(`.*`)에 잡힐 가능성 낮춤. (단, 본 기능은 .gitignore 처리를 강제하지 않는다.)

### 슬라이드 식별 알고리즘

곡의 마크다운을 파싱해서 `SongSpec`을 얻은 뒤, 패치를 적용할 슬라이드를 다음 순서로 매칭한다.

1. **해시 매칭**: 패치의 `slide_hash`와 현재 각 슬라이드의 본문 해시(SHA-256(`Slide.main.encode("utf-8")`))를 비교. 일치하는 첫 슬라이드에 적용.
2. **인덱스 fallback**: 해시 매칭 실패 시, 패치의 `slide_index`가 현재 슬라이드 수 범위 안이면 그 인덱스 슬라이드에 적용. 단, 이 경우 패치는 "drift" 상태로 표시 (운영자에게 알림).
3. **고아 패치**: 둘 다 실패 → 패치는 어느 슬라이드에도 적용되지 않음. 일반 편집 모드 알림 바에서 "원본을 찾을 수 없는 패치 N건"으로 별도 표시.

해시는 패치 적용 시점에 한 번 계산하면 되고, `slides.md`가 안 바뀌면 매번 같다.

## 컴포넌트 설계

### 새 파일

```
src/flow/services/markdown/patches.py
    - PatchStore: .patches.json 읽기/쓰기
    - SlidePatch: 패치 dataclass
    - apply_patches(spec, store) -> SongSpec: 패치를 적용한 새 SongSpec 반환

src/flow/ui/live/emergency_patch_panel.py
    - EmergencyPatchPanel(QWidget): 좌측 편집 패널
    - 신호: applied(slide_index, patched_text), reverted(slide_index), close_requested

src/flow/ui/live/discard_confirm_dialog.py
    - DiscardConfirmDialog(QDialog): Esc 시 "적용/버리기" 다이얼로그
    - 좌우 키 + Enter 키로만 조작 가능
```

### 수정될 파일

```
src/flow/services/markdown/renderer.py
    - render_slide()는 변경 없음. 호출자가 패치 적용된 SongSpec을 넘기면 됨.

src/flow/services/slide_manager.py (또는 markdown 처리 모듈)
    - SongSpec 로딩 시 PatchStore도 함께 읽고 apply_patches()
    - 패치 변경 시 캐시 무효화 + 신호 발생

src/flow/ui/main_window.py
    - 라이브 모드에서 좌우 분할 진입/이탈 로직
    - Tab 키로 패널 포커스 토글
    - 기존 라이브 단축키 핸들러에 "편집 패널 활성 시 무시" 분기 추가

src/flow/ui/editor/score_canvas.py
    - 라이브 모드에서 핫스팟 우클릭 시 "긴급 수정" 메뉴 추가 (마크다운 곡 한정)

src/flow/ui/editor/slide_preview_panel.py (또는 동등 위젯)
    - 슬라이드 우클릭 시 "긴급 수정" 메뉴 추가
    - 패치된 슬라이드 썸네일에 AMBER 닷 표시

src/flow/ui/editor/markdown_editor.py
    - 일반 편집 모드 진입 시 미반영 패치 알림 바
    - "원본에 반영 / 폐기 / 자세히" 액션
```

### 데이터 흐름

```
라이브 중 우클릭 → "긴급 수정"
    │
    ├─ MainWindow가 EmergencyPatchPanel 생성, 좌우 분할
    │
    ├─ EmergencyPatchPanel: PatchStore에서 기존 패치 있으면 로드, 없으면 원본 로드
    │
    ├─ 사용자 텍스트 편집
    │     └─ EmergencyPatchPanel 내부 미리보기만 갱신
    │
    ├─ Ctrl+Enter
    │     ├─ EmergencyPatchPanel.applied(slide_index, text) emit
    │     ├─ MainWindow → PatchStore.save_patch(...)
    │     ├─ SlideManager.invalidate(song, slide_index)
    │     ├─ 디스플레이가 그 슬라이드 송출 중 → 즉시 새 이미지 푸시
    │     └─ 분할 해제, 풀스크린 라이브 복귀
    │
    └─ Esc
          ├─ 변경 없음 → 즉시 닫기
          └─ 변경 있음 → DiscardConfirmDialog
                ├─ 적용 선택 → 위와 동일
                └─ 버리기 선택 → 분할 해제
```

## 라이브 종료 후 정리 흐름

라이브 모드를 빠져나와 곡을 일반 마크다운 편집기로 열면, 그 곡에 패치가 있는 경우 상단에 알림 바가 표시된다.

```
┌──────────────────────────────────────────────────────────┐
│ ⚠ 긴급 수정 3건이 .md 원본에 반영되지 않았습니다.      │
│                  [원본에 반영] [폐기] [자세히 보기]      │
└──────────────────────────────────────────────────────────┘
```

- **원본에 반영**: 모든 패치를 `slides.md`에 적용해 저장하고 `.patches.json` 비움. 작업은 git diff로 확인 가능
- **폐기**: 모든 패치 삭제, .md는 변경 없음
- **자세히 보기**: 패치별로 원본 vs 패치된 텍스트 diff를 보여주는 다이얼로그. 개별 적용/폐기 가능

drift 상태(인덱스 fallback으로 매칭) 또는 고아 패치는 "자세히 보기"에서만 강조 표시. 사용자가 수동 확인 후 처리하도록 유도.

## 에러 처리

| 상황 | 처리 |
|---|---|
| `.patches.json` 손상 | 로드 실패. 오류 로그 + 사용자에게 토스트 알림. 패치 무시하고 원본만 표시 |
| 패치 저장 실패 (디스크 권한 등) | 적용 액션 거부, 토스트 알림. 편집 패널은 그대로 유지 (재시도 가능) |
| 렌더링 도중 예외 | 미리보기 영역에 placeholder 이미지 + 에러 텍스트. 패치 저장은 차단 |
| 마크다운 파싱 실패 (편집 텍스트가 잘못된 마크다운) | 미리보기에 에러 표시. 적용 버튼 비활성 |

## 테스트 전략

새 기능이 라이브 안전성과 직결되므로 다음 케이스를 우선 커버한다.

### 단위 테스트 (`tests/services/test_patches.py`)
- 패치 저장/로드 round-trip
- 해시 매칭, 인덱스 fallback, 고아 패치 분기
- `apply_patches(spec, store)`가 원본 SongSpec을 변형하지 않음 (immutability)
- 다양한 손상 케이스에서 graceful degradation

### 통합 테스트 (`tests/ui/test_emergency_patch.py`, pytest-qt)
- 우클릭 → "긴급 수정" → 편집 → Ctrl+Enter → 디스플레이에 패치된 이미지 송출
- Esc with no changes → 즉시 닫힘
- Esc with changes → DiscardConfirmDialog → 좌우키로 선택 → Enter
- Tab 키 포커스 토글
- 라이브 단축키가 편집 패널 활성 시 무시됨
- "원본으로 되돌리기" → 패치 파일 항목 사라짐 + 디스플레이 복귀

### 회귀 테스트
- 기존 라이브 모드 동작 변경 없음 (긴급 수정 미사용 시)
- 마크다운이 아닌 PPT 곡에서 우클릭 시 "긴급 수정" 비활성

## 비범위 (Out of Scope)

다음은 이번 설계에서 다루지 않는다. 별도 이슈로 추적.

- PPT 곡 슬라이드의 in-app 편집 (외부 PowerPoint 필요)
- 핫스팟 좌표 / verse 매핑의 라이브 중 수정
- 배경 이미지의 라이브 중 교체
- 패치의 다중 사용자 동기화 (여러 PC에서 같은 곡 동시 편집)
- 패치 히스토리 / 버전 관리
- 패치를 다른 곡으로 옮기기

## 마이그레이션 / 호환성

- 기존 곡 데이터 변경 없음. `.patches.json`이 없는 곡은 영향 없음
- 기존 마크다운 렌더링 파이프라인 변경 없음 — 패치는 SongSpec 단계에서 합성됨
- 라이브 모드 기존 단축키 동작 변경 없음 (편집 패널이 비활성 또는 미존재 시)

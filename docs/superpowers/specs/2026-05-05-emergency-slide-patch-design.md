# 라이브 중 슬라이드 긴급 수정 설계 (Emergency Slide Patch)

- **작성일**: 2026-05-05
- **상태**: 설계 승인 대기 → 구현 플랜
- **대상 워크플로**: 마크다운 곡 (`slides.md`) 한정. PPT 곡은 본 기능에서 제외.
- **지원 작업**: (1) 기존 슬라이드 본문 편집, (2) 곡 끝에 새 슬라이드 추가 (append-only)

## 배경

라이브 송출 도중 가사 오타를 발견하는 상황이 종종 있다. 현재 Flow는 `LiveController._is_live`로 모든 편집 엔트리포인트를 차단하기 때문에, 송출을 중단하지 않고는 가사를 고칠 방법이 없다. 송출을 중단하는 것은 진행 흐름을 끊으므로 사실상 불가능하다.

마크다운 곡의 슬라이드 렌더링은 LibreOffice 등 외부 도구에 의존하지 않고 `services/markdown/renderer.py`에서 QPainter로 직접 그리기 때문에, 텍스트 변경을 수 밀리초 안에 새 이미지로 만들 수 있다. 이 점을 활용하여 라이브 도중에도 안전하게 텍스트를 고치고 즉시 디스플레이에 반영할 수 있도록 한다.

원본 `slides.md`는 건드리지 않는다. 수정 내용은 별도 "패치 파일"에 저장되어 곡과 함께 따라다니며, 라이브 종료 후 일반 편집 모드로 돌아왔을 때 사용자에게 정리(원본 반영 또는 폐기)하도록 유도한다.

## 핵심 결정

| 항목 | 선택 | 이유 |
|---|---|---|
| 적용 범위 | 마크다운 곡 한정 | PPT는 외부 도구 필요, in-app 편집 불가 |
| UI 형태 | 라이브 화면 좌우 분할 | 팝업은 라이브 화면 가림. 분할은 송출과 편집 동시 가능 |
| 진입 | 우클릭 → "긴급 수정" / "맨 끝에 슬라이드 추가" 메뉴 | 명시적이고 실수 방지 |
| 포커스 | Tab 토글 + 마우스 클릭 | 키보드만으로도 운용 가능 |
| 적용 모델 | 명시적 확인 (Ctrl+Enter) — 배치 | 자동 저장 시 청중 화면에 미완성 텍스트 노출 위험. 배치는 여러 슬라이드 수정을 한 번에 묶어 일관성 보장 |
| 저장 형식 | `<song_dir>/.patches.json` | 곡 단위 부착, 다른 프로젝트에서도 따라옴 |
| 슬라이드 식별 | 본문 해시 우선, 인덱스 fallback | 원본 .md 편집 후에도 매칭 시도 가능 |
| 라이브 종료 후 | 일반 편집 모드 진입 시 알림 바 | 임시 패치를 결국 정리하도록 유도 |
| 슬라이드 추가 | 끝에만 (append-only) | 임의 위치 삽입은 핫스팟 인덱스 시프트로 인해 라이브 중 위험. 추가는 모두 끝에 |

## UX 명세

### 진입

라이브 모드에서 우클릭 메뉴에 두 가지 항목이 있다.

**(a) "긴급 수정"** — 기존 슬라이드 본문 편집
- 스코어 캔버스의 **핫스팟** 우클릭 → 그 핫스팟이 가리키는 슬라이드 편집
- 슬라이드 **썸네일** 우클릭 → 그 썸네일이 가리키는 슬라이드 편집

**(b) "맨 끝에 슬라이드 추가"** — 새 슬라이드를 곡 끝에 append
- 슬라이드 **썸네일** 우클릭 시 메뉴에 같이 표시 (어느 썸네일이든 결과는 동일 — 곡 끝에 추가)
- 핫스팟 우클릭 메뉴에는 표시하지 않음 (추가는 핫스팟과 무관)

큰 슬라이드 프리뷰 영역(라이브/프리뷰 큰 표시) 우클릭은 본 기능의 트리거가 아니다 — 라이브 중 가장 많이 보는 영역이라 misclick 리스크가 크고, 같은 슬라이드를 가리키는 썸네일이 항상 옆에 있어서 굳이 두 경로를 둘 필요 없음.

마크다운 소스가 없는 곡(PPT 기반)에서는 두 항목 모두 비활성(disabled) + 툴팁 "PPT 곡은 외부 편집 필요".

### 분할 레이아웃

"긴급 수정" 클릭 시 라이브 화면이 좌우로 분할된다.

```
┌──────────────────┬───────────────────────────────────┐
│                  │                                   │
│  편집 패널       │  라이브 패널 (기존 라이브 UI)     │
│  (좌측, 40%)     │  (우측, 60%)                      │
│                  │                                   │
│  - 헤더          │  - 스코어 캔버스 + 핫스팟         │
│    · 닫기 버튼   │  - 슬라이드 프리뷰                │
│    · 원본 되돌리기│  - 라이브 컨트롤 (Verse, Live)   │
│  - 마크다운 입력 │                                   │
│  - 미리보기      │                                   │
│  - 적용 버튼     │                                   │
│                  │                                   │
└──────────────────┴───────────────────────────────────┘
```

좌측 비율은 40% 가량을 디폴트로 한다. 사용자가 분리바를 드래그해 조정할 수 있다.

편집 패널을 닫으면 (닫기 버튼 또는 Esc, 변경사항 처리 후) 우측이 다시 풀스크린이 된다.

### 포커스 모델

분할 상태에서 키보드 포커스는 두 패널 중 한쪽에만 있다.

- **Tab** 키 — 좌우 패널 토글
- **마우스 클릭** — 클릭한 패널 활성화
- 활성 패널: 좌측 3px **ACCENT** (`#5b8def`) 바 + 배경을 `SURFACE` → `ELEVATED` 톤으로 살짝 밝게
- 비활성 패널: 약간 어둡게 (오버레이로 5% 톤다운)

키 라우팅:
- **라이브 패널 활성 시**: 기존 라이브 단축키가 모두 정상 동작 (Space, 방향키, 숫자키, Enter, B, Esc, …)
- **편집 패널 활성 시**: 같은 키들이 텍스트 편집기로 전달됨. 기존 라이브 단축키는 동작하지 않음.

라이브 패널의 기존 키 핸들러는 `if self._is_live:` 체크 외에 "편집 패널이 활성인지"도 확인하도록 한다. (`_emergency_patch_active and _patch_focus == "editor"` 같은 조건)

Tab 키는 두 패널 모두에서 가로채야 한다. QPlainTextEdit 기본 동작(탭 문자 삽입)은 비활성화한다.

### 편집 패널 구성

```
┌──────────────────────────────────────┐
│ [◀]  슬라이드 #3 / 5  [▶]      [×]  │  ← 헤더 (네비 + 닫기)
│                       [원본으로 되돌리기] │
├──────────────────────────────────────┤
│                                      │
│  주의 사랑은 측량할 수 없네           │  ← 텍스트 입력 (QPlainTextEdit)
│  영원토록 변함이 없네                 │
│                                      │
│                                      │
├──────────────────────────────────────┤
│ ┌──────────────────────────────────┐ │
│ │                                  │ │  ← 미리보기 (작은 슬라이드 이미지)
│ │  [렌더링된 슬라이드 미리보기]    │ │
│ │                                  │ │
│ └──────────────────────────────────┘ │
├──────────────────────────────────────┤
│            [적용 (Ctrl+Enter)]       │  ← 적용 버튼
└──────────────────────────────────────┘
```

- **헤더**: ◀ ▶ 네비게이션 + 슬라이드 식별자(번호/총개수), 닫기 버튼, "원본으로 되돌리기" 버튼
- **텍스트 입력**: 슬라이드의 마크다운 본문만 (frontmatter 제외). 프로젝트 마크다운 하이라이터 적용
- **미리보기**: 텍스트 변경 시 즉시 갱신되는 작은 슬라이드 이미지 (운영자만 본다)
- **적용 버튼**: 클릭 또는 Ctrl+Enter

**모드 분기**:
- **편집 모드** (기존 슬라이드 편집): 헤더 라벨 "긴급 수정 — 슬라이드 #N", 텍스트 입력에 기존 본문 미리 채워짐, "원본으로 되돌리기" 활성
- **추가 모드** (새 슬라이드): 헤더 라벨 "새 슬라이드 추가 (#N+1)", 텍스트 입력 빈 상태, "원본으로 되돌리기" 비활성 (대상 패치가 없으므로)
- 그 외 동작은 두 모드 동일

미리보기는 `services/markdown/renderer.py`의 `render_slide()`를 호출해 만들고, frontmatter는 곡 원본 것을 그대로 사용한다.

### 편집 패널 내 슬라이드 전환 (네비게이션)

실수로 옆 슬라이드를 우클릭한 경우, 또는 한 세션에서 여러 슬라이드를 손보고 싶은 경우를 위해 헤더에 ◀ ▶ 네비게이션을 둔다.

- 헤더의 **◀ / ▶** 버튼 또는 **Ctrl+← / Ctrl+→** 단축키
- **자유 이동**: 슬라이드 사이 이동 시 다이얼로그 없이 바로 전환. 현재 슬라이드의 미적용 변경은 메모리에 그대로 보존됨
- 다른 슬라이드로 갔다가 돌아오면 입력하던 텍스트가 그대로 남아 있음

**모드별 네비게이션 의미:**

| 현재 상태 | ◀ | ▶ |
|---|---|---|
| 편집 모드, 첫 슬라이드 | 비활성 | 다음 슬라이드 (편집) |
| 편집 모드, 중간 슬라이드 | 이전 슬라이드 (편집) | 다음 슬라이드 (편집) |
| 편집 모드, 마지막 슬라이드 | 이전 슬라이드 (편집) | "새 슬라이드 추가" 팝업 → 추가 모드 진입 |
| 추가 모드 | 직전 슬라이드(기존 또는 append) 편집으로 전환 | "새 슬라이드 추가" 팝업 → 또 다른 추가 모드 |

"새 슬라이드 추가" 팝업:

```
┌────────────────────────────────────┐
│ 새 슬라이드를 추가하시겠습니까?   │
│                                    │
│         [ 예 ]    [ 아니오 ]       │
└────────────────────────────────────┘
```

- 기본 포커스: **예**
- ← → 키로 선택, Enter 로 결정
- Esc 로 팝업만 취소
- 기존 슬라이드 편집을 더 하고 싶으면 ◀ 로 돌아가 계속 편집 가능

### 편집 적용 (확인) — 배치 커밋

**Ctrl+Enter** 또는 적용 버튼은 **편집 패널을 여는 동안 누적된 모든 변경사항을 한 번에 커밋**한다.

누적 가능한 변경사항:
- 여러 기존 슬라이드의 본문 수정 (`type: "edit"` 패치들)
- 곡 끝에 추가된 새 슬라이드 (`type: "append"` 패치들, 추가한 순서대로)

확인 처리 흐름:

1. 메모리에 누적된 모든 변경사항을 `.patches.json`에 batch 저장 (한 번의 디스크 쓰기)
2. SlideManager에 한 번 변경 통보 → 해당 곡의 SongSpec 재생성
3. 디스플레이가 변경된 슬라이드 중 하나를 송출 중이면 즉시 새 이미지로 교체
4. 썸네일 스트립 갱신 (편집된 슬라이드에 AMBER 닷, 추가된 슬라이드는 끝에 표시)
5. 편집 패널 닫기, 풀스크린 라이브 복귀

적용 버튼 옆에 누적된 변경 건수 표시 (예: `[적용 3건 (Ctrl+Enter)]`).

송출 중이 아닌 슬라이드는 디스플레이에 즉시 영향 없음. 다음에 그 슬라이드가 송출되는 시점에 패치된 버전이 자동으로 나간다.

추가된 슬라이드는 핫스팟이 없으므로, 라이브 중 접근 경로는:
- 슬라이드 프리뷰 썸네일을 마우스로 클릭
- 라이브 패널의 다음/이전 슬라이드 단축키(있다면)로 끝까지 이동
- 숫자키 절 매핑은 추가 슬라이드를 자동 포함하지 않음

### 닫기 (Esc 또는 닫기 버튼)

닫을 때 누적된 변경사항 처리:

- **누적된 변경 없음** (어떤 슬라이드에도 미적용 변경 없음): 즉시 닫기
- **누적된 변경 있음** (1건 이상): 확인 다이얼로그 표시

확인 다이얼로그:

```
┌─────────────────────────────────────────┐
│ 누적된 변경사항 N건이 있습니다.        │
│ 모두 적용할까요? 모두 버릴까요?        │
│                                         │
│      [ 모두 적용 ]   [ 모두 버리기 ]    │
└─────────────────────────────────────────┘
```

- 기본 포커스: **모두 적용** (왼쪽)
- **← →** 키로 옵션 이동
- **Enter** 로 결정 실행
- 다이얼로그에서 **Esc** 누르면 다이얼로그 닫고 편집 상태로 복귀 (실수 보호)

선택 결과:
- **모두 적용**: 위 "편집 적용" 배치 커밋 흐름과 동일
- **모두 버리기**: 메모리상의 누적 변경 폐기. `.patches.json`은 변경 없음 (기존 저장된 패치는 그대로 유지). 편집 패널만 닫기

### 원본으로 되돌리기 (현재 슬라이드)

헤더 버튼. **현재 보고 있는 슬라이드 한 개**에 한해:

- 메모리상의 누적 변경(이번 세션에 입력한 텍스트)을 폐기
- 추가로, 이 슬라이드에 기존 저장된 `.patches.json` 패치가 있다면 그것도 함께 제거할지 다이얼로그로 확인
  - "이 슬라이드를 원본으로 되돌립니까? (저장된 패치도 함께 제거)" / [예] [아니오]
  - 예: 누적 변경 폐기 + 저장된 패치 즉시 제거 + 디스플레이 영향 시 즉시 갱신
  - 아니오: 누적 변경만 폐기, 저장된 패치는 유지
- 추가 모드 슬라이드(아직 미커밋)에서 누르면 그냥 그 추가 슬라이드를 폐기 — 추가 모드를 빠져나옴 (직전 슬라이드로 이동 또는 패널 닫기)

이 액션은 다른 슬라이드의 누적 변경에는 영향 주지 않음 — 진정한 "이 슬라이드만" 액션.

### 시각 표시

- **편집 중**: 좌측 패널 헤더에 큼지막한 **AMBER** 배지 "긴급 수정 중"
- **패치된 슬라이드 표시**: 운영자용 슬라이드 썸네일/프리뷰 우상단에 작은 **AMBER** 닷
  - 핫스팟 위에는 표시하지 않음 (캔버스가 이미 복잡함)
  - 디스플레이(청중 화면)에는 절대 표시하지 않음
- 라이브 패널이 비활성일 때(편집 패널 활성 시): 라이브 패널 위에 5% 톤다운 오버레이

## 데이터 모델

### 패치 파일: `<song_dir>/.patches.json`

```json
{
  "version": 1,
  "patches": [
    {
      "id": "uuid-string",
      "type": "edit",
      "slide_hash": "sha256:abc123...",
      "slide_index": 2,
      "patched_main": "주님의 사랑은 측량할 수 없네\n영원토록 변함이 없네",
      "created_at": "2026-05-05T19:42:11Z",
      "created_during": "live"
    },
    {
      "id": "uuid-string-2",
      "type": "append",
      "patched_main": "마지막에 추가한 슬라이드",
      "created_at": "2026-05-05T19:50:33Z",
      "created_during": "live"
    }
  ]
}
```

공통 필드:
- **id**: 패치 고유 ID. UI에서 패치 단위 액션 식별용
- **type**: `"edit"` (기존 슬라이드 본문 수정) 또는 `"append"` (곡 끝에 새 슬라이드 추가)
- **patched_main**: 본문 텍스트 (마크다운 형식, 슬라이드 한 블록). frontmatter나 다른 슬라이드 영향 없음
- **created_at**: ISO 8601 타임스탬프
- **created_during**: `"live"` (라이브 중 만든 긴급 수정) — 향후 다른 컨텍스트 추가 가능

`type: "edit"` 전용 필드:
- **slide_hash**: 패치 적용 시점의 원본 슬라이드 본문(`Slide.main`) 해시. 매칭 키
- **slide_index**: 패치 적용 시점의 슬라이드 인덱스. 해시 매칭 실패 시 fallback

`type: "append"` 전용 필드: 없음. 여러 append 패치는 `created_at` 오름차순으로 곡의 슬라이드 리스트 끝에 차례로 붙는다.

파일 이름 앞의 `.` 는 일부러 — 곡 폴더에서 시각적으로 덜 두드러지게 하고, 실수로 git에 안 올라가도 .gitignore 패턴(`.*`)에 잡힐 가능성 낮춤. (단, 본 기능은 .gitignore 처리를 강제하지 않는다.)

### 슬라이드 식별/적용 알고리즘

곡의 마크다운을 파싱해서 `SongSpec`을 얻은 뒤 패치를 적용한다. 두 단계:

**1단계: edit 패치 적용**
각 `type: "edit"` 패치에 대해:

1. **해시 매칭**: 패치의 `slide_hash`와 현재 각 슬라이드의 본문 해시(SHA-256(`Slide.main.encode("utf-8")`))를 비교. 일치하는 첫 슬라이드에 적용.
2. **인덱스 fallback**: 해시 매칭 실패 시, 패치의 `slide_index`가 현재 슬라이드 수 범위 안이면 그 인덱스 슬라이드에 적용. 단, 이 경우 패치는 "drift" 상태로 표시 (운영자에게 알림).
3. **고아 패치**: 둘 다 실패 → 패치는 어느 슬라이드에도 적용되지 않음. 일반 편집 모드 알림 바에서 "원본을 찾을 수 없는 패치 N건"으로 별도 표시.

**2단계: append 패치 적용**
모든 `type: "append"` 패치를 `created_at` 오름차순으로 정렬해 SongSpec.slides 리스트의 끝에 순서대로 추가. append 패치는 매칭 실패가 없다.

해시는 패치 적용 시점에 한 번 계산하면 되고, `slides.md`가 안 바뀌면 매번 같다.

```
    │
    ├─ 사용자 텍스트 편집
    │     └─ EmergencyPatchPanel 내부 미리보기만 갱신

    │     ├─ EmergencyPatchPanel.applied(patches: list[SlidePatch]) emit
    │     ├─ MainWindow → PatchStore.save_patches(patches)  # 한 번의 디스크 쓰기
    │     ├─ SlideManager가 해당 곡의 SongSpec 재생성 (apply_patches)
    │     ├─ 디스플레이가 변경된 슬라이드 중 하나 송출 중 → 즉시 새 이미지 푸시
    │     ├─ 썸네일 스트립 갱신
    │     └─ 분할 해제, 풀스크린 라이브 복귀
    │
    └─ Esc
          ├─ pending_changes 비어 있음 → 즉시 닫기
          └─ pending_changes 있음 → DiscardConfirmDialog (모두 적용 / 모두 버리기)
                ├─ 모두 적용 선택 → 위 배치 커밋과 동일
                └─ 모두 버리기 선택 → 분할 해제 (디스크 무영향)
```

## 라이브 종료 후 정리 흐름

라이브 모드를 빠져나와 곡을 일반 마크다운 편집기로 열면, 그 곡에 패치가 있는 경우 상단에 알림 바가 표시된다.

```
┌──────────────────────────────────────────────────────────┐
│ ⚠ 긴급 수정 3건이 .md 원본에 반영되지 않았습니다.      │
│                  [원본에 반영] [폐기] [자세히 보기]      │
└──────────────────────────────────────────────────────────┘
```

- **원본에 반영**: 모든 패치를 `slides.md`에 적용해 저장하고 `.patches.json` 비움. 작업은 git diff로 확인 가능
  - edit 패치: 해당 슬라이드 본문을 패치 텍스트로 교체
  - append 패치: `slides.md` 끝에 새 슬라이드 블록을 추가
- **폐기**: 모든 패치 삭제, .md는 변경 없음
- **자세히 보기**: 패치별로 원본 vs 패치된 텍스트 diff를 보여주는 다이얼로그. 개별 적용/폐기 가능
  - append 패치는 "원본 없음 → 새 슬라이드"로 표시

drift 상태(인덱스 fallback으로 매칭) 또는 고아 패치는 "자세히 보기"에서만 강조 표시. 사용자가 수동 확인 후 처리하도록 유도.

## 에러 처리

| 상황 | 처리 |
|---|---|
| `.patches.json` 손상 | 로드 실패. 오류 로그 + 사용자에게 토스트 알림. 패치 무시하고 원본만 표시 |
| 패치 저장 실패 (디스크 권한 등) | 적용 액션 거부, 토스트 알림. 편집 패널은 그대로 유지 (재시도 가능) |
| 렌더링 도중 예외 | 미리보기 영역에 placeholder 이미지 + 에러 텍스트. 패치 저장은 차단 |
| 마크다운 파싱 실패 (편집 텍스트가 잘못된 마크다운) | 미리보기에 에러 표시. 적용 버튼 비활성 |

## 테스트 전략

새 기능이 라이브 안전성과 직결되므로 다음 케이스를 우선 커버한다.

### 단위 테스트 (`tests/services/test_patches.py`)
- 패치 저장/로드 round-trip (edit, append 두 type)
- 해시 매칭, 인덱스 fallback, 고아 패치 분기 (edit)
- 여러 append 패치가 created_at 순서로 정렬되어 끝에 추가됨
- `apply_patches(spec, store)`가 원본 SongSpec을 변형하지 않음 (immutability)
- 다양한 손상 케이스에서 graceful degradation

### 통합 테스트 (`tests/ui/test_emergency_patch.py`, pytest-qt)
- 우클릭 → "긴급 수정" → 편집 → Ctrl+Enter → 디스플레이에 패치된 이미지 송출
- 우클릭 → "맨 끝에 슬라이드 추가" → 텍스트 입력 → Ctrl+Enter → 썸네일 스트립에 새 슬라이드 표시
- Esc with no pending → 즉시 닫힘
- Esc with pending → DiscardConfirmDialog ("모두 적용/모두 버리기") → 좌우키 → Enter
- 편집기 내 Ctrl+→ / Ctrl+← → 다이얼로그 없이 슬라이드 전환, pending 보존
- 슬라이드 A 편집 → 이동 → 슬라이드 B 편집 → 다시 A로 → 입력했던 텍스트 그대로 유지
- 마지막 슬라이드에서 Ctrl+→ → "추가?" 팝업 → 예 → 추가 모드 진입
- 추가 모드에서 Ctrl+→ → "추가?" 팝업 → 예 → 또 추가
- 추가 모드에서 Ctrl+← → 직전 (마지막 기존) 슬라이드 편집 모드로 전환
- 여러 슬라이드 변경 후 Ctrl+Enter → 한 번의 디스크 쓰기로 모두 .patches.json 반영
- Tab 키 포커스 토글
- 라이브 단축키가 편집 패널 활성 시 무시됨
- "원본으로 되돌리기" → 현재 슬라이드만 영향, 다른 슬라이드 pending 유지
- 핫스팟 우클릭 메뉴에 "맨 끝에 슬라이드 추가" 항목 없음 (썸네일에만 있음)
- 큰 슬라이드 프리뷰 영역 우클릭은 패치 메뉴 트리거 아님

### 회귀 테스트
- 기존 라이브 모드 동작 변경 없음 (긴급 수정 미사용 시)
- 마크다운이 아닌 PPT 곡에서 우클릭 시 "긴급 수정" 비활성

## 비범위 (Out of Scope)

다음은 이번 설계에서 다루지 않는다. 별도 이슈로 추적.

- PPT 곡 슬라이드의 in-app 편집 (외부 PowerPoint 필요)
- 슬라이드 임의 위치 삽입 (현 스펙은 append-only. 임의 위치는 핫스팟 인덱스 시프트 보정 필요)
- 핫스팟 좌표 / verse 매핑의 라이브 중 수정
- 배경 이미지의 라이브 중 교체
- 패치의 다중 사용자 동기화 (여러 PC에서 같은 곡 동시 편집)
- 패치 히스토리 / 버전 관리
- 패치를 다른 곡으로 옮기기

## 마이그레이션 / 호환성

- 기존 곡 데이터 변경 없음. `.patches.json`이 없는 곡은 영향 없음
- 기존 마크다운 렌더링 파이프라인 변경 없음 — 패치는 SongSpec 단계에서 합성됨
- 라이브 모드 기존 단축키 동작 변경 없음 (편집 패널이 비활성 또는 미존재 시)
